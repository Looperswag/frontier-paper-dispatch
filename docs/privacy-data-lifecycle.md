# 隐私、保留与数据处置边界

本项目是单所有者的私人阅读系统，不是多租户服务。以下内容描述当前代码真实行为；“建议”不代表已经自动执行。

## 数据在哪里

| 数据 | 位置 | 可能包含的私人内容 |
| --- | --- | --- |
| 画像、选源 | 本地 `config/`；启用云任务时短暂写入 GitHub 托管 runner | 角色、项目、兴趣与不关注方向 |
| 密钥 | 本地 `.env`、Web 私有环境或 GitHub Actions Secrets | API key、service role、邮件授权码、Webhook URL/token |
| 论文与日报 | Supabase | 元数据、摘要/正文片段、模型摘要、评分、历史日报 |
| 行为信号 | Supabase | 👍/👎、备注、批注、提问和回答 |
| 运维状态 | Supabase 与本地日志 | 来源健康、运行错误、投递状态、配额、告警租约；本地日志不记录反馈正文 |
| 配置备份 | 本地或用户指定介质 | 画像与 `sources.ts`；不含密钥 |

## 第三方披露

- **论文/博客/GitHub 等来源站点**：收到正常 HTTP 请求、查询词和网络元数据；不会收到个人画像。
- **DeepSeek**：排名和摘要时会收到画像以及候选论文的标题、摘要或受限正文；画像精炼时还会收到近期反馈、批注和提问摘要。不要在画像或批注中写入密码、客户数据或公司机密。
- **Supabase**：保存应用数据库和运维账本。service-role key 只允许服务端使用。
- **Server酱与 SMTP 服务商**：收到完整日报正文和反馈链接；反馈链接含签名 token，因此也应视为私人消息。
- **独立告警 Webhook**：收到事件名、严重级别、日期、受限错误描述和 correlation ID。URL/token 本身是密钥，不得放入公开环境变量。
- **GitHub Actions**：仅在显式启用云任务后，GitHub 托管 runner 会临时获得 GitHub Actions Secrets 和 `PROFILE_MD`；任务末尾删除运行文件，但 runner 与 Actions 日志仍受 GitHub 的平台策略约束。

## 当前保留行为

当前没有自动保留期清理。Supabase 中的论文、日报、反馈、批注、问答、投递记录、配额与运行/告警账本会保留到所有者主动执行经过审查的删除或项目被删除。不可变日报用于审计，并不等于法规意义上的法定留存要求。

本地采集只记录“已加载近期反馈”这一状态，不把反馈标题、原因、备注或正文写入日志。调度器使用 mode `0077` 的 umask；当前日志和 5 MiB × 3 个轮转文件均收紧为 `0600`。`.runtime/` 保存锁和最近成功标记。GitHub Actions 与第三方供应商的日志/备份保留期由各平台配置决定。

建议但尚未自动执行的策略：每季度复核行为信号与原始正文是否仍需保留；对不再需要的内容先导出和验证备份，再按依赖顺序删除。若需要强制保留期，应先增加可审计的清理作业、dry-run 报告和数据库测试，不能把本节文字当作执行器。

## 导出与删除

`npm run state:backup` 只导出画像和选源，不包含数据库导出。当前也没有覆盖所有 Supabase 私有表的一键导出；需要完整可携带副本时，应使用 Supabase 支持的备份或逻辑导出，并单独验证 Auth 所有者、表数据、向量扩展和迁移版本。

当前没有面向用户的一键删除。数据库包含级联、限制性外键、不可变日报和服务专用表；直接从浏览器或逐表随意删除可能留下不一致数据。完整删除必须由所有者在备份后，以数据库管理员身份、在事务中按依赖关系处理应用表，再按需删除 Supabase Auth 账户和项目。配置文件、`.backups/`、本地日志、GitHub Actions Secrets、邮件/微信历史及第三方备份需要分别清除；删除数据库不会自动清除这些副本。
