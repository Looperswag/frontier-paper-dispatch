# macOS 定时任务

`scripts/install-cron.sh` 会把仓库和 Node 的绝对路径写入模板，验证后一次性安装三个 LaunchAgent。launchd 日历按 Mac 本地时区解释，而流水线日期固定为 `Asia/Shanghai`，目标 Mac 应设置为上海时区：

| Label | 计划 | 命令与职责 |
|---|---|---|
| `com.frontierpapers.ingest` | 每天 22:00；失败时每 900 秒补跑；`RunAtLoad` 检查遗漏 | `ingest:send`，按计划日期生成并投递简报 |
| `com.frontierpapers.refine` | 每周日 23:00；失败时每 1800 秒补跑；`RunAtLoad` 检查遗漏 | `refine`，信号不足 3 条时只记录提示 |
| `com.frontierpapers.deliver` | 每 900 秒；`RunAtLoad` 运行 | 重试 outbox，并在 23:30 后检查缺失渠道和独立告警 |

周期唤醒和启动补跑都使用计划日期，而不是简单采用唤醒当天日期。失败或新候选不足都不会写成功标记，后续周期会再次尝试；已有成功 schedule token 时 runner 会在启动业务进程前直接退出，所以周期唤醒只是低成本去重检查。跨机器/云端重复运行还会由 Supabase 的 pipeline lease 拦截。

## 安装

仓库必须位于本地稳定路径，例如 `~/Projects/frontier-paper-dispatch`。不要放在 `Desktop`、`Documents`、`Downloads` 或 iCloud/File Provider 目录，否则 launchd 可能无权读取文件或依赖。

```bash
cd ~/Projects/frontier-paper-dispatch
npm ci
npm run doctor
npm run preflight -- --target ingest:send
bash scripts/install-cron.sh
```

`.env` 必须为 mode `0600`。手工命令可不配 `ALERT_WEBHOOK_URL`，但 `doctor` 和安装器会把独立告警视为无人值守运行的必需项。安装器先渲染并 lint 全部 plist；任一替换或加载失败时会恢复原文件。

## 验证与排障

```bash
launchctl list | grep frontierpapers

launchctl start com.frontierpapers.ingest
tail -f ingest.log

launchctl start com.frontierpapers.deliver
tail -f delivery.log

launchctl start com.frontierpapers.refine
tail -f refine.log
```

`launchctl start` 只表示已触发，请以日志和 Supabase 的 `pipeline_runs`、`source_runs`、`delivery_outbox`、`delivery_alerts` 为准。睡眠时计划可能延后；`StartInterval` 会继续补跑最近未成功的到期计划，`RunAtLoad` 也只检查最近一次，不会回放无限历史。

三个任务均使用绝对 Node 路径、mode `0077` 的 umask、单实例锁和 5 MiB × 3 日志轮转。当前日志与轮转文件权限均收紧为 `0600`。监控查询和处置顺序见 [运行监控](../docs/operations/monitoring.md)。

修改 `launchd/*.plist` 的 `StartCalendarInterval` 或 `StartInterval` 后，重新运行安装脚本即可验证并重载。

## 完整卸载

```bash
for job in deliver ingest refine; do
  plist="$HOME/Library/LaunchAgents/com.frontierpapers.$job.plist"
  launchctl unload "$plist" 2>/dev/null || true
  rm -f "$plist"
done

launchctl list | grep frontierpapers || true
```

卸载不会删除仓库、`.env`、Supabase 数据、日志或 `.runtime/` 标记；确认不再需要后由 owner 分别清理。
